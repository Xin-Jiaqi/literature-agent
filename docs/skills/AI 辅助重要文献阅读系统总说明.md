# 系统路线图

本系统用于将一篇重要英文文献从“看到但未读”逐步推进到“可调用、可复述、可引用”的状态。

核心路线如下：

```text
看到一篇文献
  ↓
放入 0_待处理
  ↓
A. 重要文献快速建档 Skill
  ↓
判断去向：
  - 重要、值得读 → 1_处理中
  - 有用但不急 → 留在 0_待处理
  - 扫过即可 → 00-已阅
  ↓
1_处理中
  ↓
围绕论文自由提问：图、公式、概念、段落、背景、和自己方向的关系
  ↓
B. 处理中对话总结 Skill
  ↓
生成一段或多段处理中草稿
  ↓
C. 最终文献笔记融合 Skill
  ↓
生成最终可调用文献笔记，并保留过程稿归档
  ↓
移动到 2-可调用
  ├─ 必要概念拆入 concepts
  └─ 需要对外表达时，用 D 转化为文章、短文或汇报大纲
```

一句话概括：

```text
A 负责判断值不值得读；
B 负责把自由问答压缩成低认知负担草稿；
C 负责把快速建档和处理中草稿融合成最终可调用笔记；
D 负责把可调用笔记转化为对外文章、短文或汇报大纲。
```

# 最高原则

本系统的最高原则是：**降低重要文献阅读的启动成本、恢复成本和调用成本**。

任何输出都应服务于：

- 更容易开始读；
- 中断后更容易恢复；
- 读完后更容易复述；
- 需要时更容易引用；
- 后续更容易改写成组会、文章、知乎、小红书或 Beamer。

不要为了格式完整而制造新的整理负担。  
不要为了显得全面而写成冗长摘要。  
不要把 AI 输出变成新的信息垃圾堆。

# 默认协作方式

如果 AI 能访问本项目文件夹，应优先直接读取论文、现有 Markdown 和相关材料，并在用户授权的任务范围内更新对应文件，避免让用户反复复制粘贴。状态文件夹的移动应以用户的明确决定为准；A 可以建议去向，但不应仅凭自己的评级擅自移动。

如果 AI 不能访问项目文件，才输出可复制的 Markdown，并请用户提供当前阶段所需的 PDF、笔记或对话内容。无论采用哪种方式，一次任务都应明确当前处理的是哪一篇文献，避免把不同论文的上下文混在一起。

# 文件夹系统

默认使用以下 Obsidian 文件夹：

```text
0_待处理
1_处理中
2-可调用
00-已阅
concepts
```

## 0_待处理

存放有意思但尚未决定是否深入阅读的文献。

主要使用：

```text
A. 重要文献快速建档 Skill
```

这一阶段的目标不是完整精读，而是基于正文 PDF 形成第一版主线判断：

- 文章讲什么；
- 为什么可能重要；
- 核心证据在哪里；
- 和用户研究方向有什么关系；
- 是否值得进入后续阅读。

## 1_处理中

存放已经决定值得读、正在处理的文献。

这一阶段不强行套模板。用户可以围绕论文自由提问，例如：

- 这段英文是什么意思；
- Fig. X 怎么理解；
- Eq. X 为什么这样写；
- 某个概念和正文主线有什么关系；
- 作者的论证逻辑是否成立；
- 这篇文章对用户自己的研究有什么启发。

每讨论完一批问题后，使用：

```text
B. 处理中对话总结 Skill
```

将最近一段尚未整理过的讨论压缩成处理中草稿，直接写入或复制到 Obsidian 文献笔记的快速建档后面。

第二次及之后使用 B 时，默认只总结上一次 B 之后的新讨论，不重复整理已总结内容。

## 2-可调用

存放已经形成最终可调用文献笔记的文献。

当一篇文章已经通过 A 建档、通过 B 积累了一段或多段处理中草稿后，使用：

```text
C. 最终文献笔记融合 Skill
```

将快速建档和处理中草稿融合成最终文献笔记。

最终结构为：

```text
可调用文献笔记
过程稿归档
```

其中：

- `可调用文献笔记` 放在最前面，用于日常复习、组会汇报、论文 introduction、后续研究调用；
- `过程稿归档` 放在后面，保留快速建档原稿和处理中草稿，便于追溯。

## 00-已阅

存放已经扫过、暂不深入处理的文献。

这些文献不是垃圾，而是已经判断过“目前不值得投入精读”的文章。以后如果研究方向变化，仍可重新找回。

## concepts

存放概念卡。

文献笔记中只解释“某个概念在本文中如何发挥作用”；`concepts` 文件夹中再整理“这个概念本身是什么”。

例如：

```text
文献笔记：nonrelativistic spin splitting 在本文中如何支持作者结论
概念卡：nonrelativistic spin splitting 的定义、物理图像、代表文献
```

# 单篇文献的内部演化

一篇文献的 Markdown 文件会经历三个阶段。

## 阶段一：快速建档

使用 A 后，文件内容大致为：

```markdown
# 文献快速建档：论文标题

## 0. 文献信息

## 1. 一句话总结与研究对象

## 2. 旧问题与新贡献

## 3. 核心证据与关键位置

## 4. 对用户的潜在价值与引用方式

## 5. 阅读优先级与建议去向
```

此时文献通常位于：

```text
0_待处理
```

如果判断值得读，移动到：

```text
1_处理中
```

如果扫过即可，移动到：

```text
00-已阅
```

## 阶段二：处理中草稿

在同一对话框中围绕论文继续自由提问。每讨论完一批问题后，用 B 生成处理中草稿。

文件内容变为：

```markdown
# 文献快速建档：论文标题

快速建档内容

---

# 处理中草稿

## Fig. 1 的分类逻辑

……

## 关于某个概念的理解

……

## 零散问题整理

……
```

处理中草稿不要求完美，也不要求有统一模板。它的作用是把零散讨论压缩成低认知负担的中间材料。

## 阶段三：最终可调用文献笔记

当文献已经基本读到可复述、可引用、可用于组会或研究启发时，用 C 将快速建档和处理中草稿融合。

最终结构为：

```markdown
# 论文标题

# 可调用文献笔记

## 文献信息

## 核心理解

## 旧问题与本文贡献

## 核心证据与关键细节

## 关键问题与当前理解

## 对我的价值与可引用内容

## 后续查证

---

# 过程稿归档

## 快速建档原稿

## 处理中草稿
```

此时文献可以移动到：

```text
2-可调用
```

# 上下文边界

如果 A/B/C 在同一个任务中连续使用，AI 可以基于当前对话上下文继续工作；若同时能访问项目文件，应以文件中的最新内容为稳定依据。

如果 A/B/C 不在同一个任务中使用、不是同一个智能体处理，或当前无法访问项目文件，用户需要提供当前任务所需材料。AI 不应假设自己能看到：

- 原始 PDF；
- 之前的聊天记录；
- Obsidian 中已有的文献笔记；
- GoodNotes 手写内容；
- Zotero 元数据；
- 之前 A/B/C 的输出。

在缺少必要材料时，AI 应基于用户提供的内容完成当前任务；如果关键信息不足，应明确标注为“后续查证”，不要假装已经确认。

# 使用原则

## 1. 不追求一口气读完

重要文献不一定一次读完。系统的目标是：

```text
每次阅读都有沉淀；
每次中断都能恢复；
最终形成可调用知识。
```

## 2. 不把 AI 当成替代阅读

AI 用于：

- 建立主线；
- 解释图、公式、概念；
- 降低英文和背景知识带来的启动成本；
- 整理对话；
- 融合笔记。

但关键判断仍需要用户结合原文、补充材料、领域背景和自己的研究方向确认。

## 3. 不让模板增加负担

A、B、C、D 是工作流工具，不是束缚。

尤其在 `1_处理中` 阶段，用户可以自由提问，不需要按照固定模板读文献。B 只在一批讨论结束后用于压缩整理。

## 4. 保留过程，但最终版在前

最终笔记不应只是把快速建档、处理中草稿和最终报告堆在一起。

正确结构是：

```text
最终可调用理解在前；
过程稿归档在后。
```

这样既方便日常调用，又保留阅读过程。

## 5. 不确定内容进入后续查证

如果某个判断依赖：

- 补充材料；
- 原文细节；
- 公式推导；
- 外部背景；
- 相关文献；

但当前材料不足，应写入：

```text
后续查证
```

不要假装已经解决。

# 四个 Skill 的分工

## A. 重要文献快速建档 Skill

用于：

```text
正文 PDF → 快速建档
```

目标：

- 判断文章讲什么；
- 判断是否重要；
- 找出核心证据；
- 判断和用户方向的关系；
- 给出阅读优先级和下一步。

## B. 处理中对话总结 Skill

用于：

```text
自由问答 → 处理中草稿
```

目标：

- 总结最近一段尚未整理过的讨论；
- 降低用户认知负担；
- 不重复已经总结过的内容；
- 不强行判断是否进最终报告；
- 生成可贴入 Obsidian 的处理中草稿。

## C. 最终文献笔记融合 Skill

用于：

```text
快速建档 + 多段处理中草稿 → 最终可调用文献笔记
```

目标：

- 去重；
- 修正；
- 融合；
- 保留关键问题；
- 区分论文内容和用户想法；
- 生成最终版在前、过程稿归档在后的完整 Markdown。

## D. 文献发表与汇报转化 Skill

用于：

```text
最终可调用文献笔记 + 必要原文依据 → 对外文章、短文或汇报大纲
```

目标：

- 根据指定平台或汇报场景重新组织表达；
- 保持论文结论、用户理解和延伸想法之间的边界；
- 核对关键数字、图表、公式及来源；
- 生成知乎/公众号长文、小红书/朋友圈短文或 Beamer 演讲大纲；
- 不反向改变 C 中作为个人知识底稿的最终文献笔记。

# 最终路线图

```text
看到一篇文献
  ↓
放入 0_待处理
  ↓
用 A 快速建档
  ↓
判断：
  - 不深入 → 00-已阅
  - 有用但不急 → 留在 0_待处理
  - 重要 → 1_处理中
  ↓
在 1_处理中自由提问
  ↓
用 B 总结一批讨论
  ↓
继续提问 / 继续 B 总结
  ↓
积累足够处理中草稿
  ↓
用 C 融合成最终可调用文献笔记
  ↓
移动到 2-可调用
  ├─ 必要概念拆入 concepts
  └─ 需要对外表达时，用 D 生成文章、短文或汇报大纲
```
